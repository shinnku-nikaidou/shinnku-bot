# shinnku-bot：微調試點

寫於 2026-11-22，接在 [v2-gaps-plan.md](v2-gaps-plan.md) 第 8 節的第 4 條之後。只是計劃，代碼還沒動。

## 0. 為什麼要做

- **提示詞這條路到頂了**。鑑別器 AUC 從裸模型的 0.870 降到加固定樣本和檢索後的 0.724，之後加人物卡、改長度、關推理、加事實清單，都停在 0.72–0.75，一直沒低於群友線 0.666。剩下的露餡是說什麼（英文字母只有我的一半、數字只有三分之一），不是怎麼說，提示詞改不了。
- **文獻也這麼說**。EMNLP 2025 測了 400 多位作者，提示裡的例子從 2 個加到 10 個幾乎沒用。IMPersona 裡 LoRA 微調的 8B 模型加記憶，被認識本人的人判成真人 44.4%，帶記憶的提示詞方案最好的只有 25%；數據越多越像，而它最多用了 1.3 萬條，我們有 80,588 對。
- **底座選 Qwen3.6-35B-A3B**。gpt-6-astra 不能微調；DeepSeek-V4.1-Flash 有 552B，沒有卡跑得動。Qwen3.6-35B-A3B 能在 Tinker 上做 LoRA，訓完量化到 4-bit 約 22G，實驗室那張 3090 Ti 能跑。它不能在 24G 的卡上自己訓：Unsloth 說 bf16 LoRA 要 74G，並且不建議對這一代模型做 4-bit QLoRA。

## 1. 結論一覽

| 要決定的 | 決定 |
|---|---|
| 底座 | `Qwen/Qwen3.6-35B-A3B`，關閉思考（Tinker 的 `qwen3_5_disable_thinking` 模板） |
| 訓練 | Tinker 上做 LoRA，rank 32；試點用 5,000 對，另留 300 對看驗證損失 |
| 訓練樣本 | 線上 harness 拼出的提示詞，去掉固定樣本、檢索和事實清單，末尾接上我當時真實的回覆；只對這最後一條算損失 |
| 回覆格式 | 純文本，一行一條消息，不用工具 |
| 評估 | 同一批 200 個留出場面（`--n 200`，seed 0），跑 `eval style` |
| 算達標 | AUC 低於群友線 0.666，或者比 gpt-6-astra 的基線低、兩者的置信區間不重疊 |
| 部署 | 達標以後再定，見第 3 節 |

## 2. 步驟

### 第 0 步：量 gpt-6-astra 的基線

換到 gpt-6-astra 之後還沒量過。`eval run --name astra --n 200`，再 `eval style --name astra`。用的是 codex 的額度，約 200 次調用。照老規矩先跑 1 條，確認 `cached_tokens` 大於 0 再跑其餘的。

這一步不依賴 Tinker，可以先做。

### 第 1 步：導出訓練數據（新命令 `shinnku corpus sft`）

- 從訓練集裡抽，不碰留出的 600 個場面。按時間加權，和固定樣本一樣近期多，因為 2025 年起我的消息明顯變長，而留出集是最新的。
- 每一對走和 `eval run` 相同的 replay 路徑，讓 harness 照線上的樣子拼提示詞，用一個只記錄、不調模型的假模型把 messages 截下來。這樣訓練時和上線時模型看到的格式逐字一致。
- 三樣東西不放進訓練樣本：
  - **固定樣本**：權重就是用來代替它的，放進去每條要多 5 萬 token。
  - **檢索**：檢索索引就是用訓練集建的，訓練對會檢索到它自己，等於把答案放進題目。
  - **事實清單**：每條多約 3k token，訓練費翻一倍。上線時照樣帶上，評估時單獨對照。
- 人物卡和群卡照常帶上，它們小，模型也該學會用。
- 末尾加一條 assistant 消息：我當時那一串回覆，一行一條。
- 寫到 `data/sft/train.jsonl` 和 `data/sft/valid.jsonl`，格式是 Tinker 認的 `{"messages": [...]}`。控制台只打印條數、每條的 token 分佈和預計訓練費。

### 第 2 步：訓練（新目錄 `finetune/`）

- 單獨的 uv 項目。`tinker-cookbook` 會帶上約 5.7G 的 torch 和 CUDA 庫，不能進 bot 自己的依賴。
- 一個幾十行的腳本：用 cookbook 的 `FromConversationFileBuilder` 讀 jsonl，`train_on_what=LAST_ASSISTANT_MESSAGE`，學習率取 cookbook 的 `get_lr`，2 輪，定期在驗證集上算損失。
- 只打印損失和進度。檢查點存在 Tinker 上。

### 第 3 步：讓 harness 能調訓好的模型

- `GatewayModel` 加一個純文本模式：不發 `tools` 和思考參數，回覆按行切成消息。`act.py` 的 `parse_action` 本來就接受純文本，不用改。
- `eval run` 能指定另一個端點和 key。Tinker 的 OpenAI 兼容端點按檢查點路徑（`tinker://…/sampler_weights/…`）調模型。
- 純文本模式沒有“沉默”。評估的場面都是我當年開了口的，試點不受影響；上線前再定，比如空回覆算沉默。

### 第 4 步：評估

同一批 200 個場面：

| 配置 | 看什麼 | Tinker 上的花費 |
|---|---|---|
| A gpt-6-astra，線上配置 | 基線，第 0 步 | 不用 |
| B 底座不微調，線上配置（帶固定樣本和檢索） | 分清是換了模型的作用，還是微調的作用 | 約 $6 |
| C 微調，不帶固定樣本、不帶檢索 | 主結果 | 不到 $1 |
| D 微調，加檢索 | 微調以後檢索還有沒有用 | 不到 $1 |
| E 微調，加事實清單 | 事實會不會拖累風格（`FACTS.md` 上線了才跑） | 不到 $1 |

除了 AUC，照常看長度分佈、連發條數和語義接近度。你的 `eval quiz` 在 C 上再做一次。

### 第 5 步：決定

- **達標**：用更多的數據（3–8 萬對）再訓一次，然後按第 3 節部署。
- **沒達標**：停下。到這裡總共花約 $30。

## 3. 部署（達標以後）

- 從 Tinker 下載 LoRA，用 cookbook 的 `build_hf_model` 合併成 bf16 的完整模型，約 70G；實驗室那臺機器有 125G 內存。底座從 hf-mirror 或 ModelScope 下載，那臺機器連不上 huggingface.co。
- 量化成 4-bit 的 GGUF，約 22G，用 llama.cpp 的服務在 3090 Ti 上跑，它提供 OpenAI 兼容的接口。Tinker 的說明裡 vLLM 對這類 MoE 模型掛 LoRA 還是實驗性的，所以先合併再量化。
- 外網連不進那臺機器，要由它主動建隧道到 bot 的服務器。
- 量化以後再跑一次第 4 步的 C，確認風格沒有掉。
- 分工：說話走微調模型；判斷考題、決定搜什麼、看圖仍然用 gpt-6-astra；備用模型不變。
- 那張卡是和別人共用的，常駐服務會一直佔著約 22G 顯存。

## 5. 風險

- **Tinker 的 OpenAI 兼容端點是 beta**，支不支持工具和思考參數不清楚。純文本模式就是為了不依賴它們。
- **35B-A3B 比 gpt-6-astra 笨**，難題和代碼會答得差。考題本來就不答；新聞之類有檢索兜著。
- **微調模型的老毛病**：突然跳話題、硬塞記住的細節（IMPersona 都觀察到了）。
- **會背出訓練數據裡的話**，包括群裡別人說過的。
- **一次答好幾個人**：純文本沒有 `to` 編號，分不清哪句回誰。評估不涉及，上線前要處理。
- **量化可能損失風格**，第 3 節裡要重新量。

## 6. 需要你做的

1. 註冊 Tinker，把 key 寫進 `.env` 的 `TINKER_API_KEY`，或者跑 `tinker auth login`。
2. 同意把約 5,300 段群聊（包括別人說的話）上傳到 Tinker 訓練。這和現在回覆、蒸餾時把內容發給網關上游是同一類事，但換了一家，而且會存成檢查點。
3. 第 5 步之後決定要不要全量訓練和部署，以及能不能長期佔用實驗室的卡。
