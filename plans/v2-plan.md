写计划之后有三处变化：

- **不建测试 bot**。按你的要求直接用正式 bot 在你自己的群里测，测试时先停旧服务。
- **隐私规则放宽**。Claude 可以自己在真实数据上运行只输出结构和统计的命令；仍然不主动读内容。
- **依赖提前精简**。你要求升到最新依赖，而全量升级会连带下载几个 G 的 torch 和 CUDA 库。所以 `pyproject.toml` 现在只列新 bot 用到的包（都是最新版），同步时用 `uv sync --inexact`，旧 bot 用的包留在虚拟环境里不删。切换前不要跑不带 `--inexact` 的 `uv sync`，否则旧 bot 重启会失败。

### 目前的评估结论（2026-11-12）

真实数据规模（两个群都导完后）：共 108 万条消息，你的发言 22.9 万条，回复对 80,588 个，每个群留出最新的 300 个作测试集。下面三项实验是在第二个群导到一半时跑的，当时回复对约 7 万个。

| 实验 | 结果 | 说明 |
|---|---|---|
| 仅占位人设，100 个留出场面 | 99 个开口；单条长度中位数 bot 9 字、真人 11 字；连发 bot 1.84 条、真人 1.56 条；出戏率 20.8%；延迟中位数 2.0 秒 | 不带任何真实样本的起点 |
| 同一批回复换裁判 | glm-5.3 低推理 48.5%，高推理 46.5%；kimi-k3 57.8%（只判出 45 条）；deepseek-v4-pro 29.3% | 裁判之间差得太多，而且有的明显偏向 bot |
| 离线检索验证，100 个场面 | 检索到的场面里“我说过的话”与真实回复的最高相似度 0.544，随机场面 0.504；72% 的场面检索胜过随机；检索耗时中位数 103 毫秒 | 检索有效，幅度不大 |

由此改了两点：

- **模型裁判不当主指标**。它在这里不可靠，默认关闭（`--judge` 才开）。主指标改为“bot 回复与真实回复的语义接近度”、长度和连发分布、出戏率，以及你本人做的 `eval quiz`。
- **评估默认小样本**。默认 40 条、并发 4。原因见下。

还没验证的：加上固定样本块和检索之后，比仅占位人设好多少。这组对比因为额度用尽没跑成。

### 提示词大小：定在约 5 万 token

2026-11-12 实测了大提示词（内容是真实对话片段，价格为标价，额度实扣其 60%）：

| 提示词 | 缓存没命中 | 缓存命中 |
|---|---|---|
| 1.2 万 token（107 个场面） | 约 4 秒 | 1.5 秒 |
| 5.0 万 token（520 个场面） | 2.8 秒，约 $0.0075 | 未单独测 |
| 9.8 万 token（1,100 个场面） | 3.4 秒，$0.0147 | 2.6 秒，$0.0003 |
| 36.5 万 token（3,900 个场面） | 6.6–8.2 秒，约 $0.04–0.055 | 3.5 秒，$0.0011 |

缓存在第一次请求之后要过 20–60 秒才生效，所以冷启动后一分钟内的回复都是全价。

你定的大小是 5 万 token 左右，对应 520 个固定样本（`ANCHOR_SCENES=520`，现为默认值）。实际量到的提示词是 50,124 token。样本放大后效果是否更好没有做对比评估，这是你决定不跑的。

### 网关额度

`opencode-go/*` 的模型共用一个滚动额度。2026-11-12 凌晨比较裁判时，并行跑了三轮高推理强度的重判，把额度用尽了，约半小时内所有请求返回 429。以后批量评估要先估规模，真机测试前不要把额度花在评估上。

## 1. 目标

把 5 年前写的 Telegram bot 从零重写，让它的说话方式和开口时机都像 shinnku 本人。

判断标准是盲测：给同一段上文，一句是本人当年真实说的，一句是 bot 生成的，裁判模型和本人都分不出来（准确率接近 50%）。

## 2. 已定的决定

| 决定 | 说明 |
|---|---|
| 不微调 | 这台服务器没有独立显卡，网关也不提供微调；靠上下文实现 |
| 默认模型 | `opencode-go/deepseek-v4.1-flash`，endpoint 和 key 走 `.env` |
| 身份设定 | 第一人称“我就是 shinnku”，提示词里不出现“扮演、模仿、AI、助手、用户”；被问是不是 bot 时按本人的方式回应，不出戏 |
| 账号类型 | bot 账号（Bot API），不用本人账号 |
| 技术栈 | Python 3.13、uv、python-telegram-bot、SQLite，不换框架 |
| 聊天记录 | Claude 不看内容，只看结构 |

## 3. 实测事实（2026-11-11）

全部用合成的群聊内容测的，没有用到真实聊天记录。

| 项 | 结果 | 对设计的影响 |
|---|---|---|
| 工具调用 | 可用。`tool_choice=required` 时 2.6 秒返回，推理只有 12–16 token（2 次） | “说话”和“沉默”做成工具 |
| JSON 模式 | 可用，但触发了 538 token 的分析式推理（“我们被问到……”），耗时 13 秒（1 次） | 不用 JSON 模式 |
| 关闭推理 | `thinking: {"type": "disabled"}` 有效，推理 token 为 0。`reasoning_effort: none` 和 `enable_thinking: false` 无效 | 作为对照配置，由评估决定开不开 |
| 提示缓存 | 15k token 的提示第二次请求命中 15104 token 缓存，耗时从 11.2 秒降到 7.4 秒 | 稳定内容放提示词最前面 |
| 延迟 | 带推理的普通短请求 5.8–8.9 秒（8 次）；更早有一次 22 秒 | 在线路径只走一次模型调用 |
| 流式 | 可用，先出推理（4.5 秒）再出正文（7.3 秒） | 输出只有十来个 token，不需要流式 |
| 第一人称推理 | 身份用第一人称写时，推理多数是括号里的内心独白，但仍会出现“作为阿橘”“符合我一贯的风格”这类出戏句 | 把“出戏率”做成指标；风格靠真实样本传达，少写规则条文 |
| embedding | 网关没有 embedding 模型 | 在本机 CPU 上跑 |
| 全文检索 | SQLite 3.46.1 的 FTS5 trigram 可用，但少于 3 个字的查询匹配不到 | 查询用多条上文拼成的长文本，并配向量检索 |
| 服务器 | 12 核、62G 内存、无独立显卡 | 够用 |
| 旧 bot | 正以 `shinnku-bot.service` 在本目录运行（`.venv/bin/python src/main.py`，`Restart=always`） | 切换之前不能动旧文件和旧依赖 |
| 旧日志 | `logs/` 每天约 18MB、12 万行 | 很可能含聊天内容，按私密数据处理 |

## 4. 隐私规则

私密范围：`~/tg-export/`、Telegram 登录数据目录、仓库里的 `data/` 和 `logs/`。

- Claude 不读这些目录。`.claude/settings.local.json` 的拒绝规则从现有两条扩到 `data/**` 和 `logs/**`。
- 开发和测试只用合成数据：`tests/fixtures/` 里按真实结构造的假导出和假人设。
- 真实数据上的命令由你来运行。
- 命令行只打印计数、分布、耗时。含内容的结果写到 `data/reports/`，给你自己看。
- 出错时只打印异常类型和代码位置。异常消息可能带原文，所以写到 `data/reports/last_error.txt`。
- 运行日志默认不含消息文本，只记事件、id、长度、耗时和决策。含内容的追踪另写到 `data/trace/`。
- 蒸馏和评估会把聊天内容发到你的网关及其上游模型商。

## 5. 架构

### 5.1 一条消息的在线处理流程

```
1. 存库      所有类型的消息都记下来（图片、贴纸记成占位符）
2. 感知      按群防抖，把对方的连发聚成一段再处理
3. 注意力    被 @、被回复、私聊、被叫名字：直接通过
             其他情况：先过规则，后期再加分类器
4. 回忆      检索“类似场面里我说过的话”，取相关的人物卡和场景手册
5. 拼提示词  见 5.2
6. 模型调用  一次，必须调用一个工具
7. 发送前检查  不通过就带着对应规则重试一次，再不通过就沉默
8. 发送      分条发，带打字状态和按长度计算的延迟
9. 事后      后台决定要不要记笔记，不阻塞回复
```

生成期间如果被点名的那个人又发了新消息，取消并重来，最多重来一次。

### 5.2 提示词的拼法

按“越稳定越靠前”排列，前三项能命中缓存。

1. 身份内核 `SELF.md`：第一人称，用本人的口吻写。
2. 固定样本块 `anchor.txt`：几百段本人的真实对话，约 10–15k token。
3. 工具定义。
4. 这个群的群卡片，以及最近发言的人的人物卡。
5. 检索到的 20–40 个类似场面，以“我记得的事”的形式给出，不写成“请模仿以下示例”。
6. 群里最近约 30 条消息：别人的话放在 user 位，格式是 `名字: 内容`；我说过的话放在 assistant 位，不加前缀。

两条原则：

- 全程第一人称，把要求写成自我认知（“我说话很短”），不写成命令（“你必须简短”）。
- 风格主要靠第 2、5、6 项的真实样本传达。实测里把风格写成规则条文，会让推理变成“我在执行某种风格”。

### 5.3 工具

| 工具 | 作用 | 何时提供 |
|---|---|---|
| `say(messages)` | 发 1–4 条短消息 | 始终 |
| `stay_silent()` | 这次不说话 | 始终 |
| `recall(query)` | 再搜一次自己的历史，结果返回后再想一轮 | 始终，最多追加一轮 |
| `sticker(emoji)` | 从本人常用贴纸里按 emoji 选一张 | 阶段 7 |
| `remember(about, note)` | 记一条笔记 | 只在回复后的后台调用里 |

### 5.4 发送前检查

全部是确定性的代码，不调模型。

- 去掉 markdown 标记；句末标点按风格指纹处理。
- 单条长度和连发条数按风格指纹的 95 分位封顶。
- AI 腔正则（“作为一个 AI”“希望对你有帮助”“首先……其次”之类）。
- 涉及钱、现实承诺、隐私的话题：不发，并私信你。

### 5.5 记忆文件

都在 `data/persona/` 下，bot 运行时读取，部分可写。

| 文件 | 内容 | 谁写 |
|---|---|---|
| `SELF.md` | 我是谁、观点、喜好 | 蒸馏生成，你可以手改 |
| `fingerprint.json` | 风格指纹（统计量） | 语料管线 |
| `anchor.txt` | 固定样本块 | 语料管线 |
| `people/<user_id>.md` | 我对这个人的印象、怎么跟他说话 | 蒸馏生成，每晚更新 |
| `groups/<chat_id>.md` | 这个群是什么地方、常聊什么 | 蒸馏生成，每晚更新 |
| `skills/*.md` | 场景手册：某类场面下我通常怎么反应 | 蒸馏生成 |
| `diary/YYYY-MM-DD.md` | 第一人称日记 | 每晚定时任务 |
| `notes.jsonl` | `remember` 记下的零散笔记 | bot，每晚并入人物卡 |

### 5.6 离线语料管线

入口是一个命令行工具 `shinnku`。

| 命令 | 做什么 | 控制台打印 |
|---|---|---|
| `corpus probe` | 只看导出文件的结构 | 键名、类型、枚举值、计数 |
| `corpus ingest` | 流式解析 `result.json`，写入 `data/corpus.sqlite` | 消息数、各类型数、时间范围 |
| `corpus pairs` | 切会话、合并连发、生成“上文 → 我的回复”对，过滤命令、转发、纯链接、bot 消息 | 会话数、回复对数、我的发言占比 |
| `corpus holdout` | 按时间留出最近的一批回复对作测试集，其余才进入后续步骤 | 两边的数量 |
| `corpus stats` | 算风格指纹：句长、连发条数、标点、相对群友更常用的词、emoji 和贴纸、语言混用、活跃时段 | 只有数值 |
| `corpus index` | 建 FTS5 trigram 索引和向量索引 | 条数、耗时 |
| `corpus anchor` | 按时间分层抽样（近期权重高）选出固定样本块 | 条数、token 估计 |
| `corpus distill` | 用模型分块提取再合并，生成 `SELF.md`、人物卡、群卡片、场景手册；按采样做，可断点续跑 | 进度、token 用量 |

向量索引用 fastembed 在 CPU 上算，向量存成 numpy 内存映射文件，直接算点积，不引入向量数据库。模型默认选一个中文小模型，最后由评估决定。

### 5.7 评估

| 指标 | 怎么算 | 目标 |
|---|---|---|
| 盲测准确率 | 裁判模型看上文和两句回复，猜哪句是真人 | 接近 50% |
| 本人盲测 | `eval quiz` 出一份小测验，你来猜 | 接近 50% |
| 风格距离 | bot 回复和真实回复在句长、连发条数、标点率、字符 n-gram 上的分布差 | 越小越好 |
| 出戏率 | 推理或正文里出现“作为某某”“扮演”“用户”等字样的比例 | 接近 0 |
| 开口一致性 | 在抽样时刻上，“bot 想开口”和“本人当时开口了”的精确率和召回率 | 阶段 6 调 |
| 延迟和成本 | p50、p95、token、缓存命中率 | 记录 |

每个指标都支持按开关做对照：有无检索、有无固定样本块、推理开或关、换模型。裁判默认用另一家的模型，避免模型偏爱自己的输出。

## 8. 分阶段实施

阶段 1 到 4 的代码都能在合成数据上写完并测试，不用等导出结束。

### 阶段 0：导出（进行中，由你完成）

把两个群导出成 JSON 到 `~/tg-export/`，不含媒体。

### 阶段 1：骨架

- 新包 `src/shinnku_bot/`、配置、模型调用、运行时消息库。
- 最小 harness：只在被点名时回复；工具只有 `say` 和 `stay_silent`；带发送前检查和分条发送。
- 人设先用合成的占位版本。
- 命令：`/start`、`/rua`、`/okiru`、`/quiet`、`/talk`、`/status`。

验证：单元测试用假模型和假 Telegram 消息跑通；用测试 bot 在一个测试群里 @ 它，得到分条的短回复。

### 阶段 2：语料管线

- 假导出生成器，结构和 Telegram Desktop 的 `result.json` 一致。
- `probe`、`ingest`、`pairs`、`holdout`、`stats`。

验证：在假导出上各步的计数和预期一致。然后你在真实导出上跑 `probe`，把结构输出给我核对解析器，再跑其余几步。

### 阶段 3：检索和提示词

- `index`、`anchor`、混合检索、5.2 的提示词拼装。

验证：假数据上检索能召回预设的相似场面；同一前缀连续两次请求能命中缓存。

### 阶段 4：评估和基线

- `eval gen`、裁判、各项指标、`eval quiz`。
- 跑出第一组基线数字，并做对照：有无检索、有无固定样本块、推理开或关。

验证：你在真实数据上跑，得到一张指标表。之后每个改动都看这张表。

### 阶段 5：蒸馏和记忆

- `distill` 生成 `SELF.md`、人物卡、群卡片、场景手册。
- `remember` 工具、每晚的日记和人物卡更新。

验证：加入蒸馏产物后盲测准确率不变差；日记任务在假数据上能跑完。

### 阶段 6：主动发言

- 规则版注意力：冷却时间、接话窗口、每群的话痨程度、每小时调用上限。
- 分类器版：正例是本人开口的时刻，反例是本人当时在场但没说话的时刻。
- 敏感话题转给你。

验证：开口一致性指标；先在测试群里观察一天再放到正式群。

### 阶段 7：可选项

贴纸、看图，以及换一台有显卡的机器做 LoRA 微调并用同一套盲测对比。

## 10. 上线切换

1. 测试 bot 在测试群里稳定运行，盲测指标达到你满意的程度。
2. 停掉 `shinnku-bot.service`。
3. 把服务的 `ExecStart` 改成新入口，删除第 9 节列的旧文件和旧依赖。
4. 在 BotFather 里关闭正式 bot 的群隐私模式。
5. 启动服务，先把话痨程度调到最低，观察后再调高。

## 13. 风险

- 新登录的设备导出可能被 Telegram 要求等 24 小时。
- Bot API 的 bot 看不到其他 bot 的消息；群隐私模式不关就看不到普通消息。
- 你的发言占比还不知道，它决定可用的回复对有多少。
- 1–2 个字的消息全文检索匹配不到，只能靠向量检索和上文。
- 模型可能该沉默时不沉默，或者反过来。评估里单独测这一点。
- 网关有额度和限速，全量蒸馏 200 万条不现实，所以按采样做并支持续跑。
