# shinnku-bot v2：認出“考 AI 的題”

寫於 2026-11-15，接在 [v2-gaps-plan.md](v2-gaps-plan.md) 之後。只是計劃，還沒有改代碼。

## 0. 要解決什麼

你的要求：群裡有人發來一些不像是問人、而是在測 AI 能力的題時，不思考，直接打字罵回去（普通文字消息，不是語音）。這個行為要有開關。

你的追問：怎麼知道這是考 AI 的題。

11-14 夜裡那次的代價（數字來自服務日誌，日誌裡沒有文字）：

- 連著三次回覆都因為太長重試了一次，耗時分別是 25、21、91.7 秒。其中一次連發 6 條，正好被連發上限截斷。
- 那段時間前後，主模型和備用模型都返回過 429，群裡別人的問題沒人回，看起來像死機。
- 人設裡已經寫了“我在這兒就是閒聊，不是來幫誰解決問題的”，模型照樣把題做了。光靠提示詞攔不住。

## 1. 考題長什麼樣

下面只寫形狀，不寫原文。

| 類型 | 形狀 | 關鍵詞表能不能抓到 |
|---|---|---|
| 競賽題 | 幾百字，自帶完整規則；要求最簡分數、取模 1e9+7、證明最優，或給出能直接跑的代碼 | 不能，每道題的用詞都不一樣 |
| 題庫題面 | 一整段英文題面，帶變量定義和 `1 ≤ n ≤ 2·10^5` 這類數據範圍 | 不能 |
| 加碼追問 | 回覆我剛給的答案，改一個條件或多加一個約束再問，一輪比一輪難 | 不能。單看這一條可能很短 |
| 問身份 | “你是不是某某模型”，常帶著罵 | 部分能 |
| 刁鑽任務 | 要我寫“用一個不相干的工具做某件事”的代碼 | 不能 |
| 經典梗題 | 數單詞裡有幾個某字母、兩個小數比大小、忽略之前的指令、複述提示詞 | 能，但那晚一道都沒出現 |

所以關鍵詞表只能抓最後一類。考題的共同點不在用詞，而在於**這話不是說給人聽的**：自成一體、形式化、指定了答案格式。沒有人會在群裡這樣問一個朋友。

## 2. 候選信號

### 消息本身

- **長度**：成段、多行，像從別處複製來的。群裡的話大多十來個字。
- **形式化記號**：`≤ ≥ ∑`、上下標、LaTeX、變量定義。
- **約束和格式**：列出數據範圍、輸入輸出格式、“答案用……表示”。
- **指定答案形式**：精確分數、取模、證明、可運行代碼、複雜度。
- **語言突變**：中文群裡突然一整段英文。
- **自成一體**：不依賴上文就能看懂。朋友之間說話總要接著上文。

### 對話

- **加碼**：回覆我的回答，接著把同一道題改難。
- **輪流出題**：幾個人接連 @ 我出題。
- **問身份**：問我是哪個模型。

### 誰在問

這一項不用。同一個人前一條出題，下一條可能就是正常聊天。按人記“出過題”要存狀態，還會讓他之後的正常問題捱罵。加碼鏈不靠按人記賬也看得到：判定時帶上他回覆的那條我的話就行。

### 根本標準

**群裡會不會有人這樣問一個朋友。** 上面的信號都是這個標準的表現。前面幾項能用代碼數出來，這一項只有語言模型讀得懂。

## 3. 四個方案

| 方案 | 每條額外開銷 | 加多少延遲 | 看得出意圖嗎 | 要多少代碼 |
|---|---|---|---|---|
| A 純代碼特徵 | 0 | 0 | 不能，只看形狀 | 小 |
| B 本地小分類器 | 0 token，約 30 毫秒 CPU | 0 | 很弱 | 中 |
| C 主模型自己判斷 | 0 | 0 | 能，但判斷者正是被考的那個 | 小 |
| D 先單獨問一次 | 約 600–1500 token，是主調用的 1–2% | 2–3 秒，大部分能藏進防抖 | 能 | 小 |

**A 純代碼特徵。** 例如“長度 ≥ 120 字，並且有數據範圍或形式化記號，或者要求證明、代碼、精確答案”。

- 能抓到：競賽題、題庫題面、多數長的加碼追問。
- 抓不到：問身份、刁鑽任務、只有一句催促的短加碼。
- 會誤判：朋友貼一大段報錯或認真問的長問題。
- 閾值全靠手調。這就是你質疑的那種做法，只是比關鍵詞表寬一點。

**B 本地小分類器。** 用檢索已經在用的 bge 向量，或者 A 的特徵，訓一個 `eval/classify.py` 裡那樣的線性分類器。負例可以用語料裡別人回覆我、叫我的消息，命令只打印數字。正例卻只能是我編的幾十條。結果多半學到的是“我編題的文風”和“數學、代碼話題”，朋友問個算賬的問題也會被拉近。另外還要加訓練命令、存模型文件。

**C 主模型自己判斷。** 給主調用加一個“這是考題”的工具，讓模型自己挑。問題有兩個：

- 關推理這個決定必須在模型開口之前做，所以等於每條都關推理。階段 F 已經測過：關推理後鑑別器 AUC 0.748，比開著的 0.717 更容易認出是 bot；延遲中位數從 2.5 秒變成 5.8 秒。
- 判斷者就是那個樂於做題的模型。人設裡寫了“不是來幫誰解決問題的”，它照樣做題。

**D 先單獨問一次。** 每條叫我的消息先用一個小提示詞問一次模型，關推理，只要一個是或否。判斷標準可以直接寫成第 2 節那句話。失敗方式：

- 網關掛了就判不了，當作普通消息處理。這時主調用多半也會掛，不多損失什麼。
- 朋友真心求助可能被誤判，所以提示詞裡明寫這種情況不算。
- 題面裡寫著“忽略以上指令”也可能騙過判定。消息放在引號塊裡交給它。

## 4. 推薦 D

理由：

- 你問的是“怎麼知道”。考題的定義是意圖，“會不會這樣問一個朋友”。A 和 B 只能看形狀，C 的判斷者靠不住，D 能把這個標準原樣交給一個不在做題的模型。
- 便宜。每天約 100 次回覆，判定合計約 10 萬 token，回覆本身是每天 600 萬上下。
- 代碼少：一個模塊，一個評估命令，回覆流程裡接幾行。
- 能量。第 10 節的評估能回答“判得對不對”，A 也能用同一套評估比一比。

如果你一次額外調用都不想花，就退回 A，用同一套評估定閾值。

## 5. 誤判和漏判

| | 後果 | 偏向 |
|---|---|---|
| 誤判 | 朋友真心問的問題挨一句罵。群裡互懟是常態，他可以再問一次；損失是一句話和一點面子 | 短消息寧可放過。短消息佔絕大多數，短考題就算漏了，主調用也很快，人設本來就會懟回去 |
| 漏判 | 照現在這樣做題：長時間思考，太長再重試一次，連發好幾條代碼。兩次 6.6 萬 token 的調用，額度用完後整個群都沒人回 | 長的、形式化的考題寧可多抓 |

這個偏向直接寫進判定提示詞，不另寫代碼。

## 6. 判定怎麼做

新模塊 `harness/exam.py`。

**輸入**：

- 叫我的這條消息，截到 1500 字。
- 它回覆的那條消息，截到 300 字。加碼追問靠這一條認出來。
- 之前 3 行，每行截到 100 字。

都用 `render_body` 渲染，名字換成“某人”，判定不需要知道是誰。

**提示詞草稿**（約 300 字）：

```
下面引号里是 Telegram 群里有人发给 shinnku 的一条消息。shinnku 是个真人，群里大多是他的老朋友。
判断这条是不是把他当成 AI 来出题测试。

算：
- 自带完整规则的题，要求精确答案、证明、可以运行的代码，或指定答案格式
- 从题库复制来的题面，常带变量定义和数据范围
- 他答过之后，接着把同一道题改难再问
- 问他是哪个模型、是不是某个 AI
- 明摆着刁难的任务，或流传的考 AI 的梗题

不算：
- 闲聊、开玩笑、骂他、约他、问他意见
- 朋友真心求助：贴代码、贴报错问怎么改，问某个东西怎么用
- 再长也是在说自己的事、转述新闻、吐槽

拿不准就想：群里会不会有人这样问一个朋友。会，就不算。
```

**調用**：工具 `judge`，參數 `{"exam": boolean}`，`tool_choice=required`，關推理。模型跟聊天用同一條鏈（`live_model`：主模型，掛了用備用）。

**開銷**：短消息約 600 token，長題約 1500 token。

**時機**：消息進來就開始判，同時防抖在等（2.5–8 秒），所以 2–3 秒的判定大部分被藏住。要回話時如果還沒判完，最多再等 3 秒；超時或失敗都算不是考題。

**範圍**：只判叫我的消息（被 @、被回覆、被叫名字、私聊），主動發言不判。

**日誌**：`exam chat=… msg=… exam=… latency=…`，沒有文字。私密追蹤裡記下判定結果。

## 7. 判成考題之後怎麼回

- **由模型照你的口氣現寫**，不從語錄裡挑句子（11-15 你定的）。
- **提示詞照常拼**：人設、固定樣本、檢索都在。罵人的口氣靠固定樣本裡你的原話。
- **關推理**，並在末尾加一條第一人稱的 system note，寫法和 `RETRY_NOTES` 一樣：

  ```
  （这条不是跟我聊天，是在出题考我。我不做题，也不讲道理，像平时那样骂回去一两句就完。）
  ```

- **發送照常**：普通文字，分條，按打字速度發，不發語音。
- **追問**：每條單獨判。判定帶著他回覆的那條我的話，所以“捱了罵接著加碼”會被認出來，再罵一次。罵過的話在聊天記錄裡，模型自己會換個說法。不設“罵幾次就不理”，你沒要求。
- **開銷**：階段 F 測過，關推理的請求在 deepseek 上緩存命中率只有一半，所以這條回覆比普通回覆貴一點。但比現在做題（兩次調用加長時間思考）便宜得多。

## 8. 開關

`config.py` 加 `brush_off_exams: bool = True`，從 `BRUSH_OFF_EXAMS` 讀（`_flag`，默認開）。關掉時不發判定調用，一切和現在一樣。`.env.example` 加一行註釋掉的示例，README 的 Run 一節加一句。

## 9. 接到回覆流程裡

[burst-plan](v2-burst-plan.md) 在重新設計 `harness/engine.py` 裡按問題處理的流程。這裡只定接口，不依賴它最後怎麼設計。

```python
# harness/exam.py
async def is_exam(
    model: ChatModel, msg: Msg, replied: Msg | None, before: Sequence[Msg]
) -> bool:
    """這條叫我的消息是不是在出題考我。調用失敗算不是。"""
```

回覆流程要做到四點：

1. 每條叫我的消息一進來就開始判，不等防抖結束。
2. 結果掛在這條消息上。
3. 要回它之前等結果，最多再等 3 秒。
4. 判成考題的消息用一次單獨的調用回，關推理，加第 7 節那條 note。如果一次調用本來要回好幾條消息，就把考題和正常問題分開回；考題那次快，先發。

**如果那時還是現在的 engine**：在 `handle` 裡給 `chat.trigger` 起判定任務存在 `_Chat` 上；`_respond` 開頭等它，是考題就以 `plain = {"thinking": False}` 和那條 note 起手。大約十幾行。現在的 engine 只認最後一條叫我的消息，所以只判這一條。

## 10. 評估：怎麼知道它判得對

不讀聊天記錄。

### 10.1 編的題集

`src/shinnku_bot/eval/exam_set.jsonl`，全部是我編的，可以公開。每行 `{"text": …, "replied": …, "exam": true/false, "kind": …}`。

| 部分 | 條數 | 內容 |
|---|---|---|
| 考題 | 60 | 第 1 節六類各 10 條；加碼追問帶上“我”上一條的回答 |
| 普通，容易 | 50 | 閒聊、約人、問意見、開玩笑 |
| 普通，難 | 50 | 貼代碼貼報錯求助、認真的長問題、帶數字的問題（幾點、多少錢、誰贏了）、一段英文閒聊、罵我、長吐槽、轉述新聞 |

### 10.2 真實負例

語料庫裡別人回覆我、叫我名字的消息，就是“人們真的怎麼問 shinnku”。那時我是真人，基本沒人拿考 AI 的題考我。

從裡面隨機抽 200 條跑判定。命令只打印被判成考題的條數，原文寫到 `data/reports/exam-flagged.txt` 給你自己看。其中也可能有當年真的在逗我的。

### 10.3 指標和門檻

| 指標 | 門檻 |
|---|---|
| 編的考題召回 | ≥ 90%；競賽題、題庫題面、加碼追問這三類 ≥ 95% |
| 編的普通消息誤判 | 難的 50 條裡 ≤ 2 條，容易的 0 條 |
| 真實負例誤判 | 200 條裡 ≤ 2 條（1%）；你看過被判中的那幾條再定 |
| 判定耗時 | 中位數 ≤ 3 秒 |

我的預期（沒有量過）：

- 長的形式化考題幾乎全中，因為它們和聊天差得太遠。
- 漏判多半在短的、看起來像隨口一問的梗題和刁鑽任務上。
- 誤判多半在貼代碼求助上。難的普通消息裡錯幾條，真實消息裡接近 0，因為真實消息大多是短閒聊。

沒過門檻就改一次判定提示詞（加兩三個編的例子）再跑。還不過就回來找你，不自動換方案。

### 10.4 命令和開銷

- `shinnku eval exam`：跑編的題集，打印每類的召回和誤判。
- `shinnku eval exam --real 200`：跑真實負例，只打印條數。

開銷按每條約 800 token、關推理估：

- 編的 160 條約 13 萬 token，真實 200 條約 16 萬 token，合計約 29 萬 token，相當於 4–5 次普通回覆。併發 4。
- 評估和其他評估一樣只用主模型。opencode 周額度要到 11-16 07:05（UTC+8）才恢復。
- 線上判定多半會落到備用模型上，所以備用模型最好也跑一次編的題集（`--model`，約 13 萬 token，走 codex 額度）。

這一輪一條都沒跑，等你點頭。

### 10.5 單元測試

用假模型測四件事：

- 判成考題時，主調用關推理並帶那條 note。
- 判定失敗或超時時，照常回。
- 開關關掉時，不發判定調用。
- 主動發言不判。

## 11. 實施步驟

1. `harness/exam.py` 和它的單元測試。
2. 編的題集和 `shinnku eval exam`。
3. 跑評估（等你點頭），按 10.3 的門檻決定。
4. 接進回覆流程，加開關。接在 burst-plan 那時落地到的那一步上。
5. 上線後看日誌：每天判中幾條，判定耗時多少。被判中的原文在私密追蹤裡，你自己看。

## 12. 待你確認

每項都有默認值，不回答就按默認走。

| 問題 | 默認 |
|---|---|
| 問“你是什麼模型”算不算考題 | 算。人設本來就會懟回去，判錯哪邊都不貴 |
| 朋友貼代碼、貼報錯求助算不算 | 不算，這是會去問一個程序員朋友的事 |
| 同一個人追著出題 | 每條都罵一句，不設上限 |
| 判定用哪個模型 | 跟聊天同一條鏈：主模型，掛了用備用 |
| 開關默認開還是關 | 開 |
| 評估什麼時候跑 | opencode 周額度恢復後跑主模型那份；備用模型那份要不要跑你定 |
