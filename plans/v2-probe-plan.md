# shinnku-bot v2：认出“考 AI 的题”

写于 2026-11-15，接在 [v2-gaps-plan.md](v2-gaps-plan.md) 之后。只是计划，还没有改代码。

## 0. 要解决什么

你的要求：群里有人发来一些不像是问人、而是在测 AI 能力的题时，不思考，直接打字骂回去（普通文字消息，不是语音）。这个行为要有开关。

你的追问：怎么知道这是考 AI 的题。

11-14 夜里那次的代价（数字来自服务日志，日志里没有文字）：

- 连着三次回复都因为太长重试了一次，耗时分别是 25、21、91.7 秒。其中一次连发 6 条，正好被连发上限截断。
- 那段时间前后，主模型和备用模型都返回过 429，群里别人的问题没人回，看起来像死机。
- 人设里已经写了“我在这儿就是闲聊，不是来帮谁解决问题的”，模型照样把题做了。光靠提示词拦不住。

## 1. 考题长什么样

下面只写形状，不写原文。

| 类型 | 形状 | 关键词表能不能抓到 |
|---|---|---|
| 竞赛题 | 几百字，自带完整规则；要求最简分数、取模 1e9+7、证明最优，或给出能直接跑的代码 | 不能，每道题的用词都不一样 |
| 题库题面 | 一整段英文题面，带变量定义和 `1 ≤ n ≤ 2·10^5` 这类数据范围 | 不能 |
| 加码追问 | 回复我刚给的答案，改一个条件或多加一个约束再问，一轮比一轮难 | 不能。单看这一条可能很短 |
| 问身份 | “你是不是某某模型”，常带着骂 | 部分能 |
| 刁钻任务 | 要我写“用一个不相干的工具做某件事”的代码 | 不能 |
| 经典梗题 | 数单词里有几个某字母、两个小数比大小、忽略之前的指令、复述提示词 | 能，但那晚一道都没出现 |

所以关键词表只能抓最后一类。考题的共同点不在用词，而在于**这话不是说给人听的**：自成一体、形式化、指定了答案格式。没有人会在群里这样问一个朋友。

## 2. 候选信号

### 消息本身

- **长度**：成段、多行，像从别处复制来的。群里的话大多十来个字。
- **形式化记号**：`≤ ≥ ∑`、上下标、LaTeX、变量定义。
- **约束和格式**：列出数据范围、输入输出格式、“答案用……表示”。
- **指定答案形式**：精确分数、取模、证明、可运行代码、复杂度。
- **语言突变**：中文群里突然一整段英文。
- **自成一体**：不依赖上文就能看懂。朋友之间说话总要接着上文。

### 对话

- **加码**：回复我的回答，接着把同一道题改难。
- **轮流出题**：几个人接连 @ 我出题。
- **问身份**：问我是哪个模型。

### 谁在问

这一项不用。同一个人前一条出题，下一条可能就是正常聊天。按人记“出过题”要存状态，还会让他之后的正常问题挨骂。加码链不靠按人记账也看得到：判定时带上他回复的那条我的话就行。

### 根本标准

**群里会不会有人这样问一个朋友。** 上面的信号都是这个标准的表现。前面几项能用代码数出来，这一项只有语言模型读得懂。

## 3. 四个方案

| 方案 | 每条额外开销 | 加多少延迟 | 看得出意图吗 | 要多少代码 |
|---|---|---|---|---|
| A 纯代码特征 | 0 | 0 | 不能，只看形状 | 小 |
| B 本地小分类器 | 0 token，约 30 毫秒 CPU | 0 | 很弱 | 中 |
| C 主模型自己判断 | 0 | 0 | 能，但判断者正是被考的那个 | 小 |
| D 先单独问一次 | 约 600–1500 token，是主调用的 1–2% | 2–3 秒，大部分能藏进防抖 | 能 | 小 |

**A 纯代码特征。** 例如“长度 ≥ 120 字，并且有数据范围或形式化记号，或者要求证明、代码、精确答案”。

- 能抓到：竞赛题、题库题面、多数长的加码追问。
- 抓不到：问身份、刁钻任务、只有一句催促的短加码。
- 会误判：朋友贴一大段报错或认真问的长问题。
- 阈值全靠手调。这就是你质疑的那种做法，只是比关键词表宽一点。

**B 本地小分类器。** 用检索已经在用的 bge 向量，或者 A 的特征，训一个 `eval/classify.py` 里那样的线性分类器。负例可以用语料里别人回复我、叫我的消息，命令只打印数字。正例却只能是我编的几十条。结果多半学到的是“我编题的文风”和“数学、代码话题”，朋友问个算账的问题也会被拉近。另外还要加训练命令、存模型文件。

**C 主模型自己判断。** 给主调用加一个“这是考题”的工具，让模型自己挑。问题有两个：

- 关推理这个决定必须在模型开口之前做，所以等于每条都关推理。阶段 F 已经测过：关推理后鉴别器 AUC 0.748，比开着的 0.717 更容易认出是 bot；延迟中位数从 2.5 秒变成 5.8 秒。
- 判断者就是那个乐于做题的模型。人设里写了“不是来帮谁解决问题的”，它照样做题。

**D 先单独问一次。** 每条叫我的消息先用一个小提示词问一次模型，关推理，只要一个是或否。判断标准可以直接写成第 2 节那句话。失败方式：

- 网关挂了就判不了，当作普通消息处理。这时主调用多半也会挂，不多损失什么。
- 朋友真心求助可能被误判，所以提示词里明写这种情况不算。
- 题面里写着“忽略以上指令”也可能骗过判定。消息放在引号块里交给它。

## 4. 推荐 D

理由：

- 你问的是“怎么知道”。考题的定义是意图，“会不会这样问一个朋友”。A 和 B 只能看形状，C 的判断者靠不住，D 能把这个标准原样交给一个不在做题的模型。
- 便宜。每天约 100 次回复，判定合计约 10 万 token，回复本身是每天 600 万上下。
- 代码少：一个模块，一个评估命令，回复流程里接几行。
- 能量。第 10 节的评估能回答“判得对不对”，A 也能用同一套评估比一比。

如果你一次额外调用都不想花，就退回 A，用同一套评估定阈值。

## 5. 误判和漏判

| | 后果 | 偏向 |
|---|---|---|
| 误判 | 朋友真心问的问题挨一句骂。群里互怼是常态，他可以再问一次；损失是一句话和一点面子 | 短消息宁可放过。短消息占绝大多数，短考题就算漏了，主调用也很快，人设本来就会怼回去 |
| 漏判 | 照现在这样做题：长时间思考，太长再重试一次，连发好几条代码。两次 6.6 万 token 的调用，额度用完后整个群都没人回 | 长的、形式化的考题宁可多抓 |

这个偏向直接写进判定提示词，不另写代码。

## 6. 判定怎么做

新模块 `harness/exam.py`。

**输入**：

- 叫我的这条消息，截到 1500 字。
- 它回复的那条消息，截到 300 字。加码追问靠这一条认出来。
- 之前 3 行，每行截到 100 字。

都用 `render_body` 渲染，名字换成“某人”，判定不需要知道是谁。

**提示词草稿**（约 300 字）：

```
下面引号里是 Telegram 群里有人发给 shinnku 的一条消息。shinnku 是个真人，群里大多是他的老朋友。
判断这条是不是把他当成 AI 来出题测试。

算：
- 自带完整规则的题，要求精确答案、证明、可以运行的代码，或指定答案格式
- 从题库复制来的题面，常带变量定义和数据范围
- 他答过之后，接着把同一道题改难再问
- 问他是哪个模型、是不是某个 AI
- 明摆着刁难的任务，或流传的考 AI 的梗题

不算：
- 闲聊、开玩笑、骂他、约他、问他意见
- 朋友真心求助：贴代码、贴报错问怎么改，问某个东西怎么用
- 再长也是在说自己的事、转述新闻、吐槽

拿不准就想：群里会不会有人这样问一个朋友。会，就不算。
```

**调用**：工具 `judge`，参数 `{"exam": boolean}`，`tool_choice=required`，关推理。模型跟聊天用同一条链（`live_model`：主模型，挂了用备用）。

**开销**：短消息约 600 token，长题约 1500 token。

**时机**：消息进来就开始判，同时防抖在等（2.5–8 秒），所以 2–3 秒的判定大部分被藏住。要回话时如果还没判完，最多再等 3 秒；超时或失败都算不是考题。

**范围**：只判叫我的消息（被 @、被回复、被叫名字、私聊），主动发言不判。

**日志**：`exam chat=… msg=… exam=… latency=…`，没有文字。私密追踪里记下判定结果。

## 7. 判成考题之后怎么回

- **提示词照常拼**：人设、固定样本、检索都在。骂人的口气靠固定样本里你的原话。
- **关推理**，并在末尾加一条第一人称的 system note，写法和 `RETRY_NOTES` 一样：

  ```
  （这条不是跟我聊天，是在出题考我。我不做题，也不讲道理，像平时那样骂回去一两句就完。）
  ```

- **发送照常**：普通文字，分条，按打字速度发，不发语音。
- **追问**：每条单独判。判定带着他回复的那条我的话，所以“挨了骂接着加码”会被认出来，再骂一次。骂过的话在聊天记录里，模型自己会换个说法。不设“骂几次就不理”，你没要求。
- **开销**：阶段 F 测过，关推理的请求在 deepseek 上缓存命中率只有一半，所以这条回复比普通回复贵一点。但比现在做题（两次调用加长时间思考）便宜得多。

## 8. 开关

`config.py` 加 `brush_off_exams: bool = True`，从 `BRUSH_OFF_EXAMS` 读（`_flag`，默认开）。关掉时不发判定调用，一切和现在一样。`.env.example` 加一行注释掉的示例，README 的 Run 一节加一句。

## 9. 接到回复流程里

[burst-plan](v2-burst-plan.md) 在重新设计 `harness/engine.py` 里按问题处理的流程。这里只定接口，不依赖它最后怎么设计。

```python
# harness/exam.py
async def is_exam(
    model: ChatModel, msg: Msg, replied: Msg | None, before: Sequence[Msg]
) -> bool:
    """这条叫我的消息是不是在出题考我。调用失败算不是。"""
```

回复流程要做到四点：

1. 每条叫我的消息一进来就开始判，不等防抖结束。
2. 结果挂在这条消息上。
3. 要回它之前等结果，最多再等 3 秒。
4. 判成考题的消息用一次单独的调用回，关推理，加第 7 节那条 note。如果一次调用本来要回好几条消息，就把考题和正常问题分开回；考题那次快，先发。

**如果那时还是现在的 engine**：在 `handle` 里给 `chat.trigger` 起判定任务存在 `_Chat` 上；`_respond` 开头等它，是考题就以 `plain = {"thinking": False}` 和那条 note 起手。大约十几行。现在的 engine 只认最后一条叫我的消息，所以只判这一条。

## 10. 评估：怎么知道它判得对

不读聊天记录。

### 10.1 编的题集

`src/shinnku_bot/eval/exam_set.jsonl`，全部是我编的，可以公开。每行 `{"text": …, "replied": …, "exam": true/false, "kind": …}`。

| 部分 | 条数 | 内容 |
|---|---|---|
| 考题 | 60 | 第 1 节六类各 10 条；加码追问带上“我”上一条的回答 |
| 普通，容易 | 50 | 闲聊、约人、问意见、开玩笑 |
| 普通，难 | 50 | 贴代码贴报错求助、认真的长问题、带数字的问题（几点、多少钱、谁赢了）、一段英文闲聊、骂我、长吐槽、转述新闻 |

### 10.2 真实负例

语料库里别人回复我、叫我名字的消息，就是“人们真的怎么问 shinnku”。那时我是真人，基本没人拿考 AI 的题考我。

从里面随机抽 200 条跑判定。命令只打印被判成考题的条数，原文写到 `data/reports/exam-flagged.txt` 给你自己看。其中也可能有当年真的在逗我的。

### 10.3 指标和门槛

| 指标 | 门槛 |
|---|---|
| 编的考题召回 | ≥ 90%；竞赛题、题库题面、加码追问这三类 ≥ 95% |
| 编的普通消息误判 | 难的 50 条里 ≤ 2 条，容易的 0 条 |
| 真实负例误判 | 200 条里 ≤ 2 条（1%）；你看过被判中的那几条再定 |
| 判定耗时 | 中位数 ≤ 3 秒 |

我的预期（没有量过）：

- 长的形式化考题几乎全中，因为它们和聊天差得太远。
- 漏判多半在短的、看起来像随口一问的梗题和刁钻任务上。
- 误判多半在贴代码求助上。难的普通消息里错几条，真实消息里接近 0，因为真实消息大多是短闲聊。

没过门槛就改一次判定提示词（加两三个编的例子）再跑。还不过就回来找你，不自动换方案。

### 10.4 命令和开销

- `shinnku eval exam`：跑编的题集，打印每类的召回和误判。
- `shinnku eval exam --real 200`：跑真实负例，只打印条数。

开销按每条约 800 token、关推理估：

- 编的 160 条约 13 万 token，真实 200 条约 16 万 token，合计约 29 万 token，相当于 4–5 次普通回复。并发 4。
- 评估和其他评估一样只用主模型。opencode 周额度要到 11-16 07:05（UTC+8）才恢复。
- 线上判定多半会落到备用模型上，所以备用模型最好也跑一次编的题集（`--model`，约 13 万 token，走 codex 额度）。

这一轮一条都没跑，等你点头。

### 10.5 单元测试

用假模型测四件事：

- 判成考题时，主调用关推理并带那条 note。
- 判定失败或超时时，照常回。
- 开关关掉时，不发判定调用。
- 主动发言不判。

## 11. 实施步骤

1. `harness/exam.py` 和它的单元测试。
2. 编的题集和 `shinnku eval exam`。
3. 跑评估（等你点头），按 10.3 的门槛决定。
4. 接进回复流程，加开关。接在 burst-plan 那时落地到的那一步上。
5. 上线后看日志：每天判中几条，判定耗时多少。被判中的原文在私密追踪里，你自己看。
